# 导出读取与文件关闭时序 · b.3.9 工作树

2026-09-23，基于 b.3.9 发布提交 `a55ddc0`，接续 N104，第三十五轮检查 F32、F33、F35：打开素材 → 读取/打包 → 取消或写入失败 → 关闭文件 → 结束任务与重试。测试只使用临时作品，日常正文和素材未读取或修改。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N105 | 停止 ZIP 输出后就结束生成，只销毁最近开始的输入。仍在等待路径解析、打开或状态查询的操作可能迟到后重新启动读取；活动读取尚未完成时，任务也能在文件关闭前结束。正常成功同样可能先发布任务，再关闭之前读过的素材。 | 使用统一停止状态阻止迟到输入启动；跟踪已开始的异步操作、读取管线和实际关闭事件。成功、取消或失败均在输入收尾后才结束，任务服务随后发布结果或清理暂存。首次取消/读写错误保持原样。 |

只等待流管线的失败结果并不足够：读取仍在进行时，中止管线可以先报告错误，文件稍后才关闭。因此额外等待文件流的实际关闭事件；尚未交给流的文件句柄则直接关闭。不能中止的系统文件操作仍须返回后才能完成收尾，期间保留原有任务忙碌保护。

保留 N104 的缺失路径快照保护、原有文件版本/登记摘要检查、导出格式及任务清理重试机制。

## 复现和验证

新增 [14 个回归场景](../scripts/tests/export-streams.test.mjs)：修复前 13 个失败、1 个兼容场景通过，修复后全部通过。

- 文档分享和完整项目包分别在路径解析、文件打开、文件状态查询的返回处暂停，再取消；未完成操作收尾前任务不结束，迟到结果不启动素材读取。
- 两种导出都在一次真实文件读取尚未返回时取消；不发起下一次读取，等待素材句柄关闭后返回原取消原因。
- 两种导出的素材读取已完成，但关闭尚未结束时，成功任务继续等待；避免仅凭 ZIP 写完就提前发布。
- ZIP 输出在路径解析、打开和状态查询期间失败：停止后续输入，保留原写入错误，释放文件后允许重试。
- 文件状态查询报错、关闭延迟的兼容场景：继续等待关闭并保留原错误，随后可正常导出。

每个场景在独立进程中保留真实文件句柄、流和 ZIP 生成，仅延后指定临时文件操作的返回，或向临时输出流注入读写错误。测试直接检查任务结束时的素材句柄状态、读取次数及临时目录；成功包和重试包独立解码，比较清单摘要、原始正文、模板、元数据与 2 MiB 二进制素材。正文与模板含 BOM/CRLF，原文件逐字节保留。修复前泄漏场景的测试资源由测试收尾及独立进程退出回收。
