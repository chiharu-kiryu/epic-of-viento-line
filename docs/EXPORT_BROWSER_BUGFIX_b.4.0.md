# 浏览器导出失效与重试 · b.4.0 工作树

2026-09-24，基于 b.4.0 发布提交 `c27f8c9`，接续 N107，第三十八轮检查 F34–F35：准备 → 下载入口 → 文件失效 → 重试/重新生成 → 关闭与重新打开。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N108 | 浏览器入口直接交出下载链接，不检查临时包是否仍有效。过期或已释放时仍提示下载开始，当前窗口的“开始导出”仍被旧任务禁用；错误响应可能按原 ZIP 文件名交给浏览器。 | 点击后先读取一个字节核对可用性，再交给浏览器下载。410 显示过期提示并恢复重新生成；普通网络/服务错误保留原包，可直接重试。 |

“下载文件”使用按钮，核对成功后才建立临时下载链接；不把整个归档读入网页内存。核对沿用现有 GET/Range 接口和 10 秒请求超时，只有准确的单字节响应才被接受，异常整包响应会取消读取。该请求延续任务空闲时间，但不算完整下载，不会误回收名额。

检查期间禁用重复下载和选项，仍可取消或关闭。取消后保留可重试的包；关闭或重新打开后，旧请求的迟到结果不会再启动下载或改写新窗口。已经交给浏览器的下载，后续关闭仍保留其文件。中英文提示已补齐。

可用性核对与浏览器随后发出的文件请求是两个请求，并非事务；服务在二者之间退出或文件被外部删除，仍由浏览器报告传输失败。服务正常运行时，核对会续期；这里没有把“交给浏览器”冒充已经保存成功。

## 自动验证

新增 [12 个场景](../scripts/tests/export-browser.test.mjs)。最终测试在隔离副本中恢复原控制器、客户端、语言文件和页面后回放，**12 项全部失败**；修复后全部通过，N107 保留。

- 已过期任务不触发下载，在同一窗口重新生成后可再次下载。
- 网络、500 和超时错误不丢包；取消检查可重试。
- 关闭/重开后迟到的成功与过期结果不污染新窗口；此前已经开始下载的包不被撤销。
- 重复点击只检查一次，状态锁和语言切换正确，文件名、正文显示值及选区不变。
- 编辑服务和只读服务均执行真实客户端、HTTP 单字节检查、原文件下载、释放后的失效提示和重新生成；核对原 ZIP 的准确字节，检查不会让出未完成任务的名额。
- 不支持范围或返回错误范围时，拒绝响应并取消读取，避免将整个包缓冲到页面内存。

第一次专项中的 11 个失败均来自新测试的收尾断言：textarea 赋值时已经将 CRLF 规范成 LF，测试却拿它与磁盘格式比较。现改为对赋值后的显示值做前后比较；真实 HTTP 场景仍对磁盘正文和 ZIP 原字节严格比较。首次结果保留为 [after-initial.log](test-results/export-browser-2026-09-24/after-initial.log)，最终专项和全量均通过。原有对话框回归改为检查准备完成提示，不再依赖旧下载链接的 `href`。

## 真实浏览器验证

使用 Codex 内置浏览器打开独立临时作品，执行真实页面控件：准备分享包 → 下载 → 通过正式接口释放该测试包 → 点击旧下载按钮 → 看到过期提示及恢复的“开始导出” → 在同一窗口重新生成 → 再次下载。

两次均收到浏览器下载事件；下载目录中的两个 ZIP 与各自服务端暂存文件 **SHA-256 完全相同**，验证后仅删除这两份匹配的测试文件。正文未改变，测试标签页、服务进程和临时作品已关闭/清理。首次打开时测试作品尚未生成索引，生成该临时作品的索引并重新加载后完成验证；这项准备过程也记在 [browser.json](test-results/export-browser-2026-09-24/browser.json)。

本轮未重跑 Rust、原生保存窗口和媒体解码；未配置 `VIENTO_TEST_ARCHIVE_BINARY`，两组原生归档检查明确跳过。[b.4.0 发布证据](test-results/release-b.4.0/results.json)继续保留。
