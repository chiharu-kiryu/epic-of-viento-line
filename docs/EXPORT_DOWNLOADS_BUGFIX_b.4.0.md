# 导出分段下载与名额回收 · b.4.0 工作树

2026-09-24，基于 b.4.0 发布提交 `c27f8c9`，第三十七轮检查 F32–F35：生成分享包/完整项目包 → HTTP 分段下载 → 并发及断开 → 完成判断 → 回收名额 → 再次导出。仅使用临时作品。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N107 | 服务只认一次完整响应。多个成功的分段响应已经覆盖整个 ZIP 时，仍把该任务当作未下载；三个这样的任务占满名额后，第四次导出返回 409。 | 按每个任务记录成功返回的实际字节区间，合并重叠和相邻区间。全部字节收齐且没有活动读取者后，原任务可以被下一次导出回收。 |

区间来自响应的 `Content-Range`，因此尾部范围、开放末端和超出文件末尾的请求按实际返回位置计算。重复区间不重复计数，不同任务不合并；还差一个字节也不会判为完成。304、416、未完成响应和不支持的 HEAD 请求均不计入成功区间。

中途断开的响应不证明该区间已经完整送出，因此仍保留原包供重试。这里的完成判断是服务端完整响应及区间覆盖，不是浏览器保存到磁盘的确认。区间记录最多保留 128 个不连续片段，超出时保守保留任务；重试缺段或一次完整下载仍可完成。原有过期、释放、读取者保护和删除失败重试继续适用。

## 复现与验证

新增 [8 个场景](../scripts/tests/export-downloads.test.mjs)。同一份最终测试文件直接运行在未修改的 b.4.0 代码上，**7 项失败、1 项兼容场景通过**；修复后全部通过。

- 分享包和完整项目包分别连续下载三份，每份分两次收齐；核对拼接字节、独立解码 ZIP、清单大小与 SHA-256，随后成功创建第四份。
- 乱序、重叠、重复片段和单字节缺口，以及开放范围、尾部范围和末端截断。
- 不同任务各有一半不能混成完整任务；304、416 和 HEAD 不会让出名额，完整重试正常。
- 真实 HTTP 读取途中断开：暂停指定文件读取，客户端收到首段后断开，等待服务端关闭并收尾，再验证缺段保护和重新下载。
- 三个真实分段响应并发持有任务，按不同顺序收尾；最后一个读取者退出前不会回收文件。

所有测试对临时作品的正文、模板、登记和图片/视频/音频测试字节进行前后比较，并在结束时核对导出暂存目录为空。服务器处理完成后才检查名额，避免把客户端收完字节误当作服务端文件已关闭。没有测试媒体解码。
