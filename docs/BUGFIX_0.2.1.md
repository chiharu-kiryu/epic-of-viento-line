# 0.2.1 故障排查与修复

本文保留故障修复时的构建编号与验证过程；这些修复现已统一纳入 [b.2.8](RELEASE_b.2.8.md)，当前交付以 b.2.8 为准。

2026-09-09。本轮检查覆盖数据分离后的转换、素材登记、引用解析、文件服务及桌面运行。作品格式继续使用 v2，原有正文、大纲、模板、素材及登记身份保持不变。

## 已复现并修复

| 故障触发方式 | 原行为 | 修复后的行为 |
| --- | --- | --- |
| 自定义标准化输出指向程序源码或外置素材目录 | 允许写入生成文件，并将其中的原有文本当成旧缓存清理 | 在写入前检查程序、作品、外置素材及真实路径，拒绝直接路径和指向这些位置的链接 |
| 已打开作品中的素材失去读取权限 | 未捕获的读取流异常导致整个编辑服务退出 | 先打开文件再发响应，捕获传输错误；单个失败请求不影响继续编辑 |
| 素材改名并保留旧路径后，新文件占用该旧路径 | 新登记成功，但后续读取因别名冲突失败，索引无法重建 | 检查整批待登记路径，出现冲突时不写入任何新登记；旧登记和原文件保留 |
| 在 Linux 含冒号的目录中自动登记作品，或使用非法清单字段 | 网页工具接受的清单可能被桌面版拒绝 | 自动名称采用可迁移的后备名称；拒绝负时间、非法名称和多余的目录声明字段 |
| 正文引用 `assets/portrait.png`、其他素材子目录或编码后的文件名 | 强行拼入 `assets/images/`，或无法对应元数据，产生错误路径与未解析引用 | 按作品根解析任意素材目录，URL 解码一次后按原始文件名关联登记 |
| 图片文件名包含 `#`、`%` | 文件名被当作 URL 片段或转义序列，实际请求另一个文件 | 分别编码路径段；保留文件名原意，并支持稳定 ID 图片地址 |
| 请求 MP4、音频、字体、SVG，或拖动媒体播放位置 | 多种类型统一返回二进制类型；Range 请求返回整个文件 | 返回对应媒体类型，支持单区间、后缀、开放区间读取及越界响应，保持流式传输 |
| 素材更新后浏览器缓存仍有效，或条件请求同时携带 ETag 和日期 | 可继续显示旧素材；不匹配的 ETag 仍可能得到 304 | 稳定地址都要求重新验证；ETag 优先于日期判断 |

这八组回归用例在修复前均失败，修复后通过。所有故障复现都使用临时作品与临时文件，未在当前作品中制造冲突或删除素材。

## 校验

- 系统 Node.js 18 与应用内置 Node.js 24 分别执行完整 JavaScript 检查，覆盖 71 项测试、脚本语法、API 契约、模板对齐及 885 份文档索引。
- Rust 使用 release 配置运行 7 项常规测试，覆盖导入导出、校验失败回滚、外置素材、兼容标记和原始字节保留。约 3 GB 的既有作品迁移包保留同一份，不因程序修复而复制。
- Linux 0.2.1 AppImage 验证原生窗口中的打开、编辑、源文/区块转换、保存、取消丢弃、返回作品库、关闭确认与处理服务退出，并验证带特殊文件名的 SVG 实际显示和媒体区间请求。
- 交付前将当前作品逐文件对照现有迁移包清单，确认 4,095 个文件的大小和 SHA-256 一致；程序源码另行归档，不与素材重复打包。

媒体条件请求与单区间响应遵循 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)。当前不实现 multipart 多区间响应；遇到这类请求会返回完整文件。读取及断开处理使用 Node 的 [流式 pipeline](https://nodejs.org/api/stream.html#streampipelinesource-transforms-destination-options)。

## 修复完成时的交付

`dist/current/` 保存 0.2.1 Linux x86_64 AppImage、完整作品迁移包、0.2.1 源码归档、校验值和使用说明。旧的 0.2.0 程序和源码包在新包验证后删除；构建缓存通过 `npm run clean` 清理。

本轮不改变作品库格式、故事结构或素材内容，也不代表已穷尽所有潜在缺陷。其他系统的安装包仍需在目标平台构建验证。
