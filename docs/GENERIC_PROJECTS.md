# 通用 OC 项目

b.2.8 的新建作品库使用 v3 格式。应用创建空白正文目录和六份可修改的通用模板，不预置具体作品、游戏属性或素材。v1、v2 项目及迁移包继续读取原来的目录，不会因更新程序而自动搬动源文件。

## 新项目的目录

```text
我的作品/
├── workspace.json           项目身份、名称、文档类型与目录声明
├── documents/              正文；新建时为空，写作时按需创建子目录
│   ├── characters/         角色档案，背景与经历包含在角色正文中
│   ├── stories/            独立故事
│   ├── places/             地点
│   ├── organizations/      组织
│   ├── concepts/           设定
│   └── …                   可以选择自己的子目录
├── templates/              项目自己的起始模板，可以直接修改
├── metadata/
│   ├── documents/          文档 ID、类型、解析方式、归属与素材关联
│   └── assets/             素材 ID、位置与内容指纹
├── assets/
│   └── media/
│       ├── images/         编辑器导入的图片
│       └── videos/         编辑器导入的视频
└── .viento/                兼容标记、本机设置、锁及可重建的 cache/
```

这些数据放在用户选定的作品文件夹，默认位于应用数据目录的 `io.viento.studio/workspaces/`，与程序安装和源码仓库分开。正文是权威内容；标题、背景、属性和章节不再复制一份到元数据中。长篇角色背景也可以用文档 ID 建立 `part-of` 归属，见 [文档模型](OC_DOCUMENT_MODEL.md)。

## 项目决定文档类型

默认菜单提供档案、角色、故事、地点、组织和设定。`workspace.json` 的 `documentTypes` 决定新建菜单、侧栏分类、默认位置、解析方式和模板，解析器按正文中的字段、章节、表格等生成布局，不要求游戏字段。空白项目进入编辑模式后可以直接新建第一份文档；取消初次草稿后也保留新建入口。

例如，在已有 `documentTypes` 数组中加入：

```json
{
  "id": "species",
  "label": "种族",
  "directory": "species",
  "parserProfile": "structured",
  "template": "species.md"
}
```

在编辑器顶部或设置中打开“项目类型与模板”，可以直接新增这个类型、编辑模板、预览并保存；新建菜单和索引会立即更新。也可以继续手工修改清单和 `templates/species.md`，重新打开项目加载。新建时可选择其他正文子目录，保存的类型不会因为位置不同而改变。

“新增类型”填写已存在的标识会提示更换，保留当前草稿；修改旧类型请从左侧列表选择。预览和保存会检查默认子目录是否符合新建规则，包括禁止隐藏目录、`node_modules` 和单段超过 255 字节的名称。旧配置仍可打开并修正，不会因此改写已有文档。

`id` 使用小写英文字母开头的字母、数字、下划线或短横线，最长 64 个字符；`label` 是显示名称。`directory` 相对于 `documents/`，空字符串表示正文根目录；类型 ID 和目录不能重复。`parserProfile` 为 `structured`（结构化档案）或 `prose`（叙事正文）。`template` 可省略；填写时相对于 `templates/`，支持 Markdown、文本、JSON 和 YAML。新建文件沿用模板的扩展名。路径不可越界，类型列表最多 100 项。

通过 `npm run workspace -- apply-definition --root 作品目录 --definition 项目定义.json` 采用共享定义时，默认只检查，添加 `--write` 才写入。省略 `template` 的类型使用自动生成的 Markdown 起始正文，同样检查默认目录与解析规则；指定的模板文件必须存在、可解析且不超过 1 MB。检查失败保留原配置，旧配置中的无效目录仍可打开并修正。实际变更在 `.viento/migrations/` 留下独立恢复日志；重复应用相同定义不新增日志，原文、素材和既有元数据不改写。

项目模板属于作品，完整备份会携带它们。修改模板影响之后新建的文档，已经写好的内容保持不变。应用不提供未经说明的类型重命名或源文件移动：已有文档的身份和类型保存在 `metadata/documents/`，手工移动源文件需要同步登记位置；仅修改目录配置不会批量改写已有文档。

## 迁移与旧项目

v3 完整备份包含 `workspace.json`、正文、模板、元数据、素材及旧版拒绝标记；缓存和本机绝对路径绑定不入包。外置素材会按稳定 ID 和原相对位置收进包内 `assets/`。导入到另一位置时逐文件校验，保留项目与文档、素材的 ID。

v1、v2 项目继续使用 `design-data/` 和 `data-template/`；v2 若没有配置类型，编辑器提供同样的通用起始类型。旧英雄文档已有的兼容解析方式和背景归属继续保留。复制旧项目保持旧格式；“新建作品库”创建 v3，不强制迁移日常作品。

验证覆盖空白新建、项目类型与模板、指定目录后的类型保留、并发新建保护、PNG / WebM / MP4 嵌入、JSON / YAML 模板扩展名、保存重开，以及完整备份到另一位置的逐字节恢复。原生测试运行方式见 [桌面测试](../desktop/README.md#验证)。

## 解析与展示规则

类型可以声明 `parserOptions` 和 `fieldGroups`。前者定义标题字段、叙事中允许的字段、长文本及其结束边界；后者按精确字段名安排展示分组，未选内容始终保留。默认仍按原文章节顺序展示。详见 [工作流与类型契约](PROJECT_WORKFLOW.md)。

项目定义优先于登记记录中的旧 `parserProfile`。统一解析入口供标准化、模板预览、素材预览与文档导出调用；已登记的类型不会因文件目录改变而重新猜测。旧目录只在没有项目定义时提供兼容。
