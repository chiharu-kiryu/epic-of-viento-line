# 素材引用与分享导出修复 · b.3.1 工作树

2026-09-23。基于 b.3.1 发布提交 `759fe3c`，沿 F31、F32、F38 检查“正文引用 → 引用索引 → 分享包”。本轮修复不增加版本号，不提交或替换安装程序。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N59 | 索引能识别正文中的裸 `asset:UUID` 和旧图片路径，但分享导出只收集实际嵌入的媒体和手动附件，可能漏带图片、音频；缺失声明也会被误报为导出成功。 | 与索引共用解析后的媒体收集和旧图片路径解析，携带声明及旧路径引用；未嵌入正文的素材列为关联素材。未知 ID 或缺失文件明确失败，修复引用后可重试。 |
| N60 | 同一素材分别作为主题曲、配音等角色绑定时，导出页面重复追加播放器。 | 每篇文档的关联素材按素材身份去重；正文中已嵌入的素材不再追加，各篇附属故事仍各自保留需要的展示。原有角色绑定不改写。 |
| N61 | 相对图片路径按带 `docs-standard/` 前缀的预览路径计算，合法的 `../../assets/立绘.png` 被丢弃，也没有相应缺失提示。 | 以原始正文目录解析相对路径；v2、v3 均能登记引用、补齐图片列表并报告未找到登记的路径。 |

## 数据与兼容

分享包继续保留未经改写的 `sources/`、原始登记及素材字节；旧别名匹配到原来的 UUID，百分号文件名只按 URL 语义解码一次。尚未登记但真实存在的本地图片也能随分享包导出，使用包内路径展示，不为它创建作品登记。

代码围栏和 YAML 注释中的示例继续排除；缺失素材不会生成可下载的成功任务。完整项目包的格式与原生导入实现没有变化，文档阅读分享包仍不能作为完整项目恢复包。本轮只在临时作品中验证，没有操作日常作品或素材。
