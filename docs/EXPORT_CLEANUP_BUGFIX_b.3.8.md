# 导出任务清理与失败恢复 · b.3.8 工作树

2026-09-23，基于 b.3.8 发布提交 `35d3dda`，第三十二轮检查 F32–F35：准备导出 → 下载或取消 → 关闭/过期 → 清理失败 → 重试。测试仅使用临时作品，日常正文与素材未读取或修改。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N101 | 删除临时包之前先移除任务；遇到文件暂时被占用等错误，释放重试会虚假成功，自动过期不再重试，并发释放也能提前返回成功。额度回收还可能继续生成新包，积累遗留文件。 | 删除成功后才移除任务和释放名额；并发调用等待同一次删除结果。失败保留已撤销的任务，禁止再次下载，服务运行期间每 30 秒自动重试，也可主动重试。取消或生成失败留下的目录使用相同清理机制；尚未下载及活动下载继续受保护。 |
| N102 | 下载结束后的清理异常会把成功下载变成失败，或覆盖下载中断、取消和生成失败的原始错误。 | 保留实际下载/生成结果；清理失败交给独立重试。主动释放遇到错误仍如实返回失败，下次成功必须实际清除目录。 |

默认空闲过期仍为 15 分钟。多个下载共享同一归档时，释放先撤销新下载，等最后一个读取结束后才清理。失败清理继续占用原来的名额，最多三个任务，避免故障期间不断积累临时包。测试通过缩短空闲时间验证自动重试，实际文件生成、HTTP 传输及原文件比较不替换。

## 复现和验证

新增 [9 个回归场景](../scripts/tests/export-cleanup.test.mjs)，修复前全部失败，修复后全部通过：

- 真实 HTTP 创建、准确字节下载、释放失败、同 ID 再释放及重新导出；已撤销下载返回 410。
- 并发释放等待同一次删除，两方获得相同失败结果，随后重试实际删除。
- 自动过期连续两次遇到临时占用，无后续用户请求也能回收；成功后停止重试。
- 两个读取者持有原包，先结束一个仍不删除；最后一个成功完成时，清理失败不改变下载结果。
- 读取中断和清理同时失败，保留原来的中断原因并继续回收。
- 文档分享和完整项目导出在 ZIP 已写完后取消，同时清理失败，保留取消原因、自动清理并允许重试。
- 生成的最后一次文件读取失败，清理再次失败，保留最初 I/O 错误并允许恢复后导出。
- 已完成任务的额度回收连续失败时，保留待清理记录和未领取包；恢复后先回收再生成，始终保持三份以内。
