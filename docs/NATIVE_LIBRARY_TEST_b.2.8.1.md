# b.2.8.1 作品库原生工作流实测

2026-09-13，继续验证功能图 F02/F03/F04/F06/F07/F08/F09：作品库首页的新建、打开、返回、备份和恢复。使用当前工作树重新构建的 Linux Tauri 程序，实际点选 GTK 目录、文件和保存窗口。日常安装包未替换。

## 发现并修复

**N43：已有编辑窗口时，新建或恢复会先写文件，再拒绝切换。** 实测中从编辑器返回作品库，新建另一个作品后提示“请先保存并关闭当前编辑窗口”，但第二个作品已经创建并出现在最近记录中。[修复前截图](test-results/native-library-2026-09-13/before-active-project.png)和[失败记录](test-results/native-library-2026-09-13/before-active-project.log)保留了这个状态。

现在首页禁用新建、打开其他作品和导入入口，宿主也在显示选择器、创建文件和登记之前检查编辑窗口。备份已保存内容、继续编辑和关闭窗口仍可使用。备份结束、失败重试、列表刷新或语言切换后，入口继续遵守当前会话限制；设置窗口的保存状态由设置控制器独立管理。

## 实测结果

| 操作 | 验证结果 |
| --- | --- |
| 新建 | 名称表单取消、目录选择取消都不创建作品；非法名称失败后可重试；成功创建空白 v3 项目和六个类型/模板并自动打开编辑器。 |
| 活动会话 | 界面入口禁用；从首页直接调用真实原生命令也立即拒绝，不弹选择器、不改文件或最近记录。继续编辑、关闭及再次打开正常。 |
| 打开 | 取消无写入；空目录被拒绝且保持为空；有效目录成功打开，重复打开不产生重复最近记录。 |
| 备份 | 原生保存取消后可重试；写到作品素材内部被拒绝；合法位置生成完整 ZIP，核对 CRC、文件大小、SHA-256 及源文件字节。 |
| 导入 | 取消归档选择或目标目录选择都不写入；篡改正文但保留原清单的损坏包被拒绝，恢复目录和最近记录回滚；重试有效包可自动打开。 |
| 恢复数据 | 在另一目录恢复后，清单、六份模板、正文、文档/素材元数据、图片、音频和空文件的集合与字节全部一致；原作品未变。恢复的文档和图片能在编辑器中显示。 |
| 英文 | 设置切换后真实文件夹选择器使用英文标题，取消状态同步为英文。 |

测试数据包括中文、空格、`#`、`%` 路径，以及带 BOM、CRLF 的正文；可重建缓存不进入备份。

最终原生流程完整通过并正常退出：[执行日志](test-results/native-library-2026-09-13/native-library-complete.log)、[结果与源码/构建指纹](test-results/native-library-2026-09-13/results.json)。应用全量检查 **191 通过，0 失败，0 跳过**，已启用 Node/Rust 归档互通；版本一致性、117 份 JavaScript 语法及 API 契约检查通过。Rust 库 **20 通过，0 失败**，原有 1 项真实大体积作品迁移测试仍忽略。新增的三个首页控制器回归和九个设置回归全部通过。

## 重复验证与边界

Ubuntu 24.04 x86_64，WebKitGTK/WebKitWebDriver 2.52.6，tauri-driver 2.0.6，内置 Node.js 24.20.0。运行方式见 [桌面验证说明](../desktop/README.md#验证)，新增入口是 [native-library.py](../desktop/tests/native-library.py)。

每次使用独立的 Xvfb 显示器、会话总线、配置、缓存、运行目录及临时作品。中文路径通过该显示器的剪贴板粘贴；不访问日常剪贴板。脚本等待真实列表刷新和窗口显示完成，并在截图前核对恢复内容已渲染。初始化脚本时遇到的 XTest 中文漏字、异步粘贴/窗口切换以及事件计数问题已修正；这些测试工具问题没有计为应用缺陷。

本轮覆盖 Linux 测试构建，没有测试 Windows/macOS、重新打包 AppImage 或替换已安装程序，也没有读写日常作品。图片和音频的归档字节得到核对；音视频播放和编辑流程沿用[上一轮实测](NATIVE_WORKFLOW_TEST_b.2.8.1.md)的记录。

本轮结束后清理了约 1.98 GiB 的临时构建、驱动和生成资源；测试作品、进程及挂载均已清理。保留的本轮截图和日志不足 1 MiB。
