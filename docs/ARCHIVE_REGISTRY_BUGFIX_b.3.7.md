2026-09-23，接续第三十轮，基于 b.3.7 发布提交 `ed86c84` 检查 F08、F09、F33：完整备份 → 校验包内文件与登记 → 导入新目录 → 编辑器读取及重建。全部使用临时作品，日常作品未读取或修改。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N99 | 原生归档未检查文档类型、解析方式及关系模型。校验和正确但包含未知目标、重复关系或循环归属的包能导入成功，编辑器随后拒绝读取；原生备份也可能用这种不可读的包替换旧备份。 | 按编辑器约定检查可选类型、解析方式、关系格式和目标，并迭代检查归属是否循环。失败不替换旧备份、不保留本次恢复目录；共享背景与一般引用关系继续兼容。 |
| N100 | 原生归档漏查素材名称、类别、标签和旧路径别名；不同素材的旧路径与当前位置冲突，也会放行成为不可读的项目。 | 补齐字段检查，对当前位置与旧路径统一使用 NFC、小写比较；不同素材不能占用同一个别名，同一素材的重复别名继续允许。 |

## 验证

新增 **48 个子场景**：v2、v3 各覆盖 22 种损坏登记及 2 个兼容场景。最终测试文件在发布版归档模块上回放，**44 个损坏场景失败、4 个兼容场景通过**；TAP 包括一个父汇总，计 49 项、45 失败、4 通过。修复后所有子场景及父汇总通过。

- 每个损坏样本先确认编辑器读取会拒绝，然后独立写入每个大小和 SHA-256 都正确的 ZIP。实际原生备份和导入必须同样拒绝；逐字节保留既有备份、源文件、模板、素材和登记，目标父目录及其中已有作品保持不变。
- 文档样本覆盖空类型、BOM 空白、UTF-16 长度上限、未知解析方式、错误关系结构、缺失目标、错误名称、重复关系、自归属和双向归属循环。
- 素材样本覆盖无效名称、类别、标签、缺失或越界的旧路径，以及大小写、Unicode 等价别名冲突。
- 修正登记后重新导出和导入，按原字节恢复所有文件，运行实际标准化和索引程序，确认两个角色仍共享同一份背景故事。可选旧字段、空附件角色、合法 120 UTF-16 单位的类型名、未知素材指纹及同一素材的重复别名仍可迁移。
- 既有互通测试实际运行 Node → Rust → Node 往返，核对外置图片、视频、音频、元数据和项目身份，并确认缓存、本机路径绑定不入包。
