# Android 基础拆分记录

日期：2026-09-24。基于 b.4.4（`d3709f7c`），本轮是开发改动，未增加版本号、提交推送或替换已安装程序。

## 已完成

将桌面与未来移动端可共用的逻辑提取到 `engine/`，入口为 `engine/index.mjs`。核心导入时不读取本机配置、作品目录或磁盘；依赖仅为核心内部模块和 `yaml`。

- Markdown、文本、JSON、YAML 解析及通用布局。
- 项目类型、模板默认值注入、解析规则、字段分组、旧文档归属关系。
- 字段与分段编辑的原文范围修改，保留未修改内容、BOM、换行、注释和大整数原文。
- 图片、视频、音频引用的识别与结构化正文插入。
- 文档读取、创建、版本冲突与保存流程；平台以存储接口提供具体操作。

桌面 `doc-api-service.mjs` 已实际使用新文档工作流，通过 `scripts/adapters/node-document-storage.mjs` 调用原有文件实现。原子替换、独占创建、共享事务队列、内容指纹、权限保留、元数据登记和缓存失效流程继续生效。旧模块保留兼容入口，避免出现两套实现。

补齐了桌面资源准备、源码打包、语法扫描和翻译审计对 `engine/` 的覆盖。网页加载的共享模块从程序目录提供，作品内同名目录不能替换程序代码；重建输出也不能指向引擎目录。

接口与平台职责详见 [引擎说明](../engine/README.md)。作品格式、稳定 ID 和素材布局保持现有约定，测试使用独立临时作品。

## 尚待接入

目前完成的是共享引擎和第一个实际存储适配边界，整套编辑器仍由桌面 Node 服务驱动。Android 需要继续完成：

1. Tauri Android 宿主与前端平台调用入口，替换对桌面 Node 子进程和 HTTP 服务的依赖。
2. 应用私有目录中的作品管理、元数据登记和索引；先实现项目包导入、编辑、导出，再接外部文件夹持续编辑。
3. Android 文件选择、持久授权、媒体访问与文件句柄适配，设备 URI 不写入可迁移的正文和素材引用。
4. 前后台切换、进程回收、草稿恢复，以及触屏、软键盘和窄屏布局。
5. 原生存储失败恢复、桌面与移动端项目包往返、模拟器和真机完整工作流。

内存存储只用于跨运行环境的流程测试，不承诺持久化。Android 适配必须满足接口中已列明的创建独占、错误恢复、版本检查与数据完整性要求。
