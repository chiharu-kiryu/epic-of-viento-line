# 素材拖放位置与窗口重开修复 · b.4.0 工作树

2026-09-24，基于 b.4.0 发布提交 `c27f8c9`，接续 N107–N108，第三十九轮检查 F28–F29：拖入 / 粘贴 / 选择已有素材 → 草稿插入 → 取消及重试 → 保存 → 重开与索引。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N109 | 分块编辑中，将文件拖到另一段时，捕获函数又采用仍有焦点的旧段落。素材会插错段；旧段中选中的文字还会被替换。 | 显式传入接收拖放的文本框，优先使用该段的选择位置。没有文本框目标时，继续使用当前编辑位置。 |
| N110 | 素材窗口的关闭事件异步送达。快速重开后，旧事件仍清除新窗口的插入位置，并使新列表请求失效，导致列表空白或插入被拒。 | 窗口已经重新打开时忽略旧关闭事件；新窗口保留自己的目标和列表请求。正常关闭仍清理上下文并使旧请求失效。 |

拖入仍使用目标文本框已有的光标或选择范围，本轮没有增加“根据鼠标像素定位文本光标”的行为。导入只修改草稿，保存后才写正文；取消后已登记素材可继续复用，迟到响应不能覆盖已经变化的正文或替换后的编辑块。

## 验证

新增 [9 个执行场景](../scripts/tests/media-drop.test.mjs)，直接连接实际编辑器与素材控制器。修复前 **5 失败、4 个兼容场景通过**；修复后全部通过。失败分别覆盖错误段落替换、取消后的同位置重试、真实服务批量导入，以及窗口重开的两种时序。

- 比较其他段落及目标段落的完整文本，覆盖焦点留在旧段、目标段和工具栏。
- 保留粘贴、选择已有素材、源码编辑、非文本框区域拖放的行为。
- 用可控的上传完成时间检查取消、迟到响应、替换草稿和复用已导入素材。
- 实际 HTTP 服务依次导入图片、音频、视频，核对未保存时磁盘原文不变，再由实际编辑器保存、退出并重开，重建索引并核对三个稳定素材引用。
- 核对 BOM、CRLF、未选中段落、素材原始字节、登记一致性和上传临时目录清理。
