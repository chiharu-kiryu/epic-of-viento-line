# 保存失败与重试修复 · b.3.3 工作树

2026-09-23。接续第十九轮，在 b.3.3 发布提交 `2731f2e` 的工作树检查 F18、F19、F22、F30、F45：保存失败、保留草稿、修改后重试，以及保存成功后的预览重建。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N73 | HTTP 401/403 的错误提示分支引用了尚未初始化的变量。保存被拒后，错误处理自身抛出 `ReferenceError`，无法正常呈现失败原因；共用该方法的读取与重建诊断也受影响。 | 在状态码分支内先取得错误码，再生成提示和诊断信息。未授权、令牌失效等错误正常显示，保留请求 ID；保存失败保留原基线和草稿，解除忙碌状态后可以修改、重试。 |
| N74 | 新建保存自动补上扩展名，只修改路径输入框，没有同步草稿状态。重名或写入失败后，素材预览和源路径提示仍使用不带后缀的旧路径，可能选择错误的解析方式。 | 提交前同步最终文件名、草稿路径、源路径提示及预览上下文。失败后继续使用同一路径；换名重试仍保留正文和选定类型。 |
| N75 | 文件名先校验、后补扩展名。原名称未超过 255 字节，但补后缀后超长，仍发送创建请求。 | 对最终路径再次校验；超长时本地提示、禁止提交，保留草稿，缩短名称后可继续创建。 |

保存与展示重建继续分成两个阶段：重建失败不会撤销已经保存的正文，也不会把成功保存重新标成未保存。此次修改没有改变正文格式、登记结构、稳定 ID 或服务接口。
