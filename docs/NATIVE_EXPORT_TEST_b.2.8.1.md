# b.2.8.1 编辑器导出与原生保存实测

2026-09-13，沿功能网络 F32/F33/F34/F35 检查编辑器导出、系统保存窗口、任务过期、覆盖和失败重试。使用当前工作树重新构建的 Linux Tauri 程序，版本保持 b.2.8.1；日常作品及已安装程序未改动。

## 实测发现与修复

| 编号 | 问题 | 修复 |
| --- | --- | --- |
| N44 | 宿主等用户选择位置后才打开缓存文件；保存窗口等待期间，导出任务被清理会导致保存失败。 | 显示保存窗口前打开并持有实际文件，保存时继续使用该文件。即使缓存路径已删除或被重新创建，也不会失去原包或读到替代内容；不额外复制一份缓存。取消窗口后释放持有的文件。 |
| N45 | 取消保存后任务过期，点击重试返回 410，但窗口仍保留失效任务，无法点击“开始导出”。 | 收到明确的过期状态后清除失效任务，显示中英文提示并允许原地重新生成；一般保存失败继续保留可重试的包。 |

修复前，真实 GTK 保存窗口中触发缓存清理后无法保存：[失败截图](test-results/native-export-2026-09-13/before-expiry.png)、[原生失败记录](test-results/native-export-2026-09-13/native-before.log)。新增控制器回归也复现了过期任务使按钮一直禁用：[回归失败记录](test-results/native-export-2026-09-13/ui-before.log)。

## 通过的验证

- 保存窗口已经打开时，通过真实会话中的释放接口清理任务，确认缓存目录消失后继续保存。输出与原始暂存 ZIP 逐字节相同，分享网页和引用图片齐全。
- 取消原生保存后清理任务，再次保存得到英文过期提示；同一窗口恢复生成入口，重新生成成功。
- 保存到项目素材内部被拒绝，没有写入错误位置；原导出包保持不变，可重选位置。
- GTK 覆盖确认中取消，已有备份字节不变；重试并明确点击 Replace 后，文件原子替换为完整项目包。
- ZIP 的 CRC、清单条目的大小及 SHA-256 均通过；完整包中的清单、正文、模板、元数据、图片、音频和空文件与测试作品一致，原作品及恢复副本均未被导出操作修改。
- 保存完成后，临时导出目录清空，导出窗口可以关闭；此前的新建、打开、备份、恢复与取消流程也在同次运行中通过。

最终[原生流程日志](test-results/native-export-2026-09-13/native-complete.log)正常退出。全量应用检查 **193 通过，0 失败，0 跳过**，启用 Node/Rust 归档互通；版本一致性、117 个 JavaScript 文件语法和 API 契约检查通过。Rust 库 **22 通过，0 失败**，原有 1 项真实大体积作品迁移测试仍忽略。新增 Rust 回归另覆盖缓存路径被替代、输入在等待期间变化、发布失败保留旧数据及无残留重试。

本轮通过真实释放接口执行过期定时器使用的同一清理函数，没有实际等待 15 分钟；原有定时过期回归继续通过。覆盖确认根据实际原生父子窗口识别，文件名输入后点击保存按钮，避免把 GTK 文件名补全的回车当作保存。

这是 Linux 测试构建的结果，未重新打包 AppImage，也未验证 Windows/macOS 原生文件删除与覆盖行为。测试只使用小型临时作品，未重新搬运日常的大体积素材。源码及构建指纹见[结果记录](test-results/native-export-2026-09-13/results.json)。

本轮结束后清理了约 1.98 GiB 的临时构建、驱动和生成资源；测试作品、进程及挂载均无残留。保留的本轮截图和日志不足 1 MiB。
