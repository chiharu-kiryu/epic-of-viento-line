# b.2.8 发布记录

2026-09-09。项目从 Git 中已提交的 `b.2.7` 延续到 **b.2.8**，统一包含编辑器、转换服务、Tauri 桌面程序和本次结构整理。桌面化期间使用的 `0.1.0`、`0.2.0`、`0.2.1` 为历史构建编号，后续不再单独递增该序列。

## 本次更新

- 新建项目使用通用 v3 目录，提供项目可修改的档案、角色、故事、地点、组织和设定模板；文档类型由项目清单定义，旧项目原位兼容，见 [通用项目结构](GENERIC_PROJECTS.md)。
- 编辑时可导入、选择、粘贴或拖入图片和视频，支持草稿预览与正文播放，素材保存在作品库并以稳定 ID 引用，见 [媒体嵌入](MEDIA_EMBEDDING_b.2.8.md)。
- 通用 OC 文档布局由解析器输出，类型模板不再限制自定义字段；旧角色背景通过稳定 ID 归属角色，共用背景保留一份正文，见 [OC 文档模型](OC_DOCUMENT_MODEL.md)。
- 物品属性按名称与数值逐条显示，修复多项加成挤在同一行的问题，详见 [属性显示修复](ITEM_ATTRIBUTE_DISPLAY_b.2.8.md)。
- 作品、素材和整库备份已移入系统应用数据目录，本机路径选择移入应用配置目录；开发启动、桌面选择器和无作品环境的 CI 同步调整，见 [本机数据目录](LOCAL_DATA_STORAGE.md)。

- 本版本后续按实际调用链修复了路径越界、请求异常退出、响应体超时、索引缓存竞争、重建范围和作品根传递问题，见 [调用链故障记录](CALL_PATH_BUGFIX_b.2.8.md)。
- 整理编辑器布局，完善草稿保护、源码与区块切换、保存和重建流程。
- 增加 Tauri 作品库首页、内置 Node.js 运行环境、原生窗口管理，以及带完整性校验的导入导出。
- 程序与作品数据分离；正文、模板、元数据和素材保存在独立作品库，生成索引和预览集中在缓存目录。
- 修复转换器输出误清理、素材读取异常、别名冲突、清单校验、图片引用和编码、媒体分段读取及缓存问题。复现过程与回归记录见 [故障修复记录](BUGFIX_0.2.1.md)。
- 统一作品库首页、编辑器标识、原生窗口标题、程序包、源码包和 CI 构件的发布编号。

## 版本规则

根目录 [VERSION](../VERSION) 保存对外发布号 `b.2.8`，延续项目的字母编号。Rust 直接将此文件编入程序；发行包命名与源码归档也读取同一文件。

Tauri、Cargo、npm 和系统安装器的内部版本为 **2.8.0**。当前规则是将 `字母.主号.次号` 映射为 `主号.次号.0`；这是同一次发布的兼容表示，不是另一个独立版本。字母沿用项目命名，不另行解释为新的发布通道。

以后更新 `VERSION` 时，同步 `package.json`、`package-lock.json` 的根包、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 的应用包、`src-tauri/tauri.conf.json`，以及两个首页的版本标识。`npm run check` 和桌面构建准备均会检查它们是否一致，发现分歧即停止。

`npm run desktop:build -- --bundles appimage` 会保留 Tauri 的数字安装版本，并将完成的交付文件命名为 `Viento-Studio_b.2.8_amd64.AppImage`。源码命令 `python3 desktop/package-source.py` 生成 `Viento-Studio_b.2.8_source.tar.gz`。CI 构件名同样包含 `b.2.8`。

## 数据与交付

新建项目使用 v3；原有 v2 作品继续原位读取，资料和素材不随程序版本改写。`.viento/workspace.json` 中的旧版拒绝标记仍保留原始字节，既有完整作品 ZIP 继续使用同一份。

`dist/current/` 提供 b.2.8 Linux x86_64 AppImage、源码归档、说明与 SHA-256 校验记录；完整作品包独立保存在系统应用数据目录的 `backups/`。新程序经过实际窗口流程验证后替换旧程序，构建完成后清理可重建目录。其他系统的安装包由各自平台的 CI 构建；本次本机交付为 Linux。

最终验证结果见交付目录的 `verification.json`，包括版本一致性、JavaScript 检查、Rust 测试、原生窗口版本显示与编辑保存，以及源码和作品清单的哈希校验。
