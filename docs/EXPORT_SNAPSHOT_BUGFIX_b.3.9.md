# 完整项目导出的缺失路径快照 · b.3.9 工作树

2026-09-23，基于 b.3.9 发布提交 `a55ddc0`，第三十四轮检查 F33、F35：生成项目包 → 导出期间新增内容 → 完成前检查 → 失败清理 → 重新生成与下载。测试只使用临时作品，日常正文和素材未读取或修改。

## 修复

| 编号 | 原有问题 | 修复后的行为 |
| --- | --- | --- |
| N104 | 快照只记录已有文件和目录。原本缺少素材、模板或元数据目录时，导出期间首次加入的内容可能被漏掉，但接口仍返回成功。新增兼容标记，或以相同配置、不同字节恢复公共清单，也存在遗漏。 | 将所选项目路径的“不存在”状态一并记录，写入最终包清单前重新检查；新增内容返回 409，提示保存后重试。失败包由现有任务服务清理，重新导出会包含新增文件的准确字节。 |

检查范围仍是完整项目包需要的正文、模板、元数据、素材及项目清单。使用文件自身状态检查新增路径，悬空链接也会被发现，不跟随链接读取目标。缓存变化和不属于项目包的根目录文件不影响导出；文档分享仍只检查所选正文、登记与引用素材。合法的缺省目录可以继续保持不存在，导出不会为了检查而创建它们。

## 复现和验证

新增 [18 个回归场景](../scripts/tests/export-snapshot.test.mjs)：修复前 12 个失败、6 个兼容场景通过，修复后全部通过。

- 素材根从不存在变为悬空链接时拒绝成功，保留链接与目标状态；移除测试链接后可以重试。
- 真实 HTTP 导出在规划结束后模拟第一份素材导入：失败返回 409、临时目录清空；重试下载包含新增素材，释放后再下载返回 410。
- 兼容场景覆盖 v2/v3 稳定的缺省目录、旧项目生成清单、HTML/Markdown 分享范围、无关缓存写入和已有空素材目录中新增文件的保护。

HTTP 场景在独立进程中仅对测试项目的临时目录创建时机注入一次实际素材写入，规划、ZIP 生成、传输和清理均使用生产代码。成功归档检查清单、文件数量、每个文件的大小、SHA-256，以及 BOM/CRLF 正文、模板、元数据、清单和二进制素材的准确内容；原文件保留。
